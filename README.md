# Echo — ИИ-диктофон (Go + PostgreSQL + PWA)

Рабочая локальная версия веб-приложения с адаптивным интерфейсом для компьютеров и смартфонов.

## Что уже реализовано

- Веб-приложение **открывается по адресу `/` того же Go-сервера**, дополнительные команды для фронтенда не нужны.
- Запись с микрофона, пауза, возобновление, остановка, предпрослушивание, название записи.
- Загрузка готовых аудиофайлов через диалог и drag-and-drop.
- Хранение **исходных аудиобайтов в `PostgreSQL BYTEA`**, а не в отдельной папке.
- Библиотека записей (на данный момент интерфейс получает последние 100), поиск среди загруженных записей, фильтр статусов.
- Просмотр записи, аудиоплеер, скачивание оригинала, удаление, статус обработки.
- Запуск фонового распознавания через `whisper-cli`; преобразование WebM, M4A, MP3 и др. в PCM WAV через FFmpeg.
- Генерация краткого содержания и тезисов через Ollama.
- Адаптивная светлая тема с фиолетовым акцентом; PWA (установка на устройство через браузер в поддерживаемых окружениях).
- Регистрация пользователей, вход по паролю, личные библиотеки и защита всех API-маршрутов, включая аудио.
- Реальные API-запросы, а не демонстрационные данные.
- Черновики микрофонной записи сохраняются фрагментами в IndexedDB; после перезагрузки их можно восстановить, скачать или отправить на сервер. Закрытие окна записи сохраняет черновик.
- Очередь обработки хранится в PostgreSQL, ограничивает параллелизм и восстанавливает прерванные задания после перезапуска.
- Расшифровка сохраняется до обращения к Ollama и доступна во время создания резюме или при его ошибке. Резюме можно повторить отдельно.

**Пока не реализовано**: восстановление пароля по почте, определение отдельных говорящих (диаризация), полнотекстовый поиск по всем записям, полная офлайн-библиотека и автоматическая отправка черновиков при появлении сети.

## Запуск на Windows

1. Остановите прежний Go-сервер (`Ctrl+C` в терминале).
2. Сохраните ваш текущий `.env` в безопасном месте. В новом архиве находится **только `.env.example`** — пароль мы не включаем.
3. Распакуйте архив в отдельную папку. Откройте её в VS Code.
4. Скопируйте ваш рабочий `.env` в корень проекта рядом с `main.go`.
5. Запустите PostgreSQL и убедитесь, что база `ai_recorder` существует.
6. В терминале VS Code (из папки с `main.go`) выполните:

   ```powershell
   go mod tidy
   go run .
   ```

7. Откройте **http://localhost:8080/** — появится веб-приложение, а **http://localhost:8080/health** — проверка API.

Пакеты Go загрузятся на шаге `go mod tidy`, поэтому нужен интернет для первого запуска. **Frontend не нуждается в Node.js, npm, сборке, CDN или доступе к интернету**: HTML, CSS и JavaScript встроены в Go-приложение (`embed.FS`).

## Настройка обработки с ИИ

Для запуска распознавания на ПК должны быть установлены:

- **FFmpeg** (команда `ffmpeg` в `PATH` или полный путь к `ffmpeg.exe` в `FFMPEG_CLI` файла `.env`);
- **whisper.cpp** (`WHISPER_CLI` — полный путь к `whisper-cli.exe`, `WHISPER_MODEL` — путь к скачанной GGML-модели);
- Для русской речи укажите `WHISPER_LANGUAGE=ru`: на коротких записях автоматическое определение языка может давать пустой результат. Для записей на разных языках можно выбрать `auto` (также используется, если настройка отсутствует). После изменения `.env` перезапустите сервер.
- **Ollama** с установленной моделью, указанной в `OLLAMA_MODEL` (например `ollama pull qwen3:4b`).

Пример параметров:

```dotenv
HTTP_ADDR=:8080
DATABASE_URL=postgres://postgres:YOUR_PASSWORD@localhost:5432/ai_recorder?sslmode=disable
MAX_UPLOAD_MB=200
FFMPEG_CLI=ffmpeg
WHISPER_CLI=C:\tools\whisper.cpp\build\bin\Release\whisper-cli.exe
WHISPER_MODEL=C:\tools\whisper.cpp\models\ggml-small.bin
WHISPER_LANGUAGE=ru
OLLAMA_URL=http://localhost:11434
OLLAMA_MODEL=qwen3:4b
PROCESSING_WORKERS=1
```

**Не копируйте пример слепо:** оставьте ваш рабочий пароль и реальные пути. Никогда не пересылайте `.env` и не добавляйте его в Git. В случае сбоя обработки в интерфейсе появится понятное сообщение; техническая диагностика остаётся в журнале сервера. Сохранение и воспроизведение аудио работают даже без ИИ-моделей.

## Регистрация и личные библиотеки

На экране входа есть вкладка **«Регистрация»**. Каждый пользователь выбирает уникальное имя (2–50 символов) и пароль (от 12 символов; не более 72 байт UTF-8), подтверждает пароль и сразу попадает в свою библиотеку. Имена уникальны без учёта регистра. Почта и подтверждение письмом не требуются; восстановления пароля по почте пока нет.

Списки, поиск, статистика, аудио, результаты, обработка и удаление ограничены владельцем записи. Владельца определяет сервер по сессии: передать чужой `user_id` при загрузке нельзя. Прямой запрос к чужому ID возвращает 404, как к отсутствующей записи. Фоновые обработчики видят общую очередь, но результаты наследуют доступ от записи. Идентификатор пользователя передаётся в обработчики через серверный контекст; отсутствие контекста закрывает доступ.

При обновлении автоматически создаются `auth_users`, `auth_user_sessions` и поле `recordings.user_id`. Прежний единственный аккаунт, пароль, действующие сессии и его записи переносятся. Если аккаунт ещё не был создан, старые записи без владельца может забрать только **первый аккаунт, зарегистрированный напрямую на localhost** без forwarding-заголовков. Регистрация через публичный адрес всегда даёт пустую библиотеку. Это предотвращает присвоение старых записей первым случайным посетителем. Не удаляйте старые таблицы вручную: миграция выполняется один раз и не восстанавливает отозванные сессии при следующем запуске.

Черновики хранятся в отдельной IndexedDB для каждого пользователя. Старые общие черновики переносятся только прежнему владельцу/первому локальному аккаунту, отмеченному сервером. Перенос каждого черновика атомарен; старый экземпляр удаляется после сохранения нового. При выходе записываемое аудио остаётся в черновиках своего аккаунта. Смена аккаунта в другой вкладке блокирует прежний интерфейс; незавершённые запросы и отправки привязаны к аккаунту, при котором начались. Общее использование одного профиля браузера не является криптографической изоляцией локального хранилища: для недоверенных пользователей используйте разные профили ОС/браузера.

Пароли хешируются bcrypt (стоимость 12), токены сессий случайные (256 бит), в PostgreSQL сохраняются только SHA-256-хеши токенов. Сессия действует 14 дней, переживает перезапуск и отзывается кнопкой «Выйти» на текущем устройстве. Повторный вход обновляет текущий токен. Общий предел регистрации/входа — 10 попыток в минуту на процесс; это ограничение учитывает нагрузку bcrypt на небольшой сервер, а не доверенные IP-заголовки прокси.

Cookie имеет `HttpOnly`, `SameSite=Strict` и `Path=/`. Для публичного адреса используется `Secure` cookie с префиксом `__Host-`; для локального HTTP предусмотрена отдельная cookie. Токены и пароль не записываются в localStorage. На разных адресах приложения вход выполняется отдельно.

## Доступ через интернет

Для доступа с телефона через обычный браузер используйте HTTPS-туннель или HTTPS reverse proxy. Авторизация уже встроена; Cloudflare Access можно использовать как дополнительный слой.

1. Если есть старые записи без владельца, сначала зарегистрируйте свой аккаунт на `localhost`. Проверьте регистрацию и вход.
2. Настройте туннель к `http://localhost:8080` с публичным HTTPS-адресом. Прокси должен сохранять исходный `Host` (он должен совпадать с `Origin` браузера); forwarding-заголовки не считаются подтверждением локального доступа.
3. Откройте HTTPS-ссылку на другом устройстве и войдите. HTTPS нужен и для cookie, и для доступа к микрофону. Публичный HTTP для входа не поддерживается.
4. Пока компьютер, PostgreSQL и Go не работают, приложение недоступно. Для обработки также нужны локальные модели.

Все `/api/*`, кроме явно разрешённых маршрутов входа и проверки сессии, требуют действующую cookie. Это касается скачивания, прослушивания, удаления, результатов и статистики. `/health` и статические файлы оболочки доступны без входа; API-ответы не кешируются.

## API

| Метод | Маршрут | Что делает |
|---|---|---|
| GET | `/health` | Проверка сервера |
| GET | `/api/auth/status` | Состояние входа, ID и имя текущего пользователя |
| POST | `/api/auth/register` | Регистрация: JSON с `username` и `password`, выдаёт cookie |
| POST | `/api/auth/login` | Вход: JSON с `username` и `password`, выдаёт cookie |
| POST | `/api/auth/logout` | Выход и отзыв текущей сессии |
| GET | `/api/stats` | Общая статистика |
| POST | `/api/recordings` | Создать запись (multipart поле `audio`) |
| GET | `/api/recordings?limit=100` | Последние записи |
| GET | `/api/recordings/{id}` | Метаданные записи |
| GET | `/api/recordings/{id}/audio` | Прослушивание оригинала |
| GET | `/api/recordings/{id}/audio?download=1` | Скачивание оригинала |
| POST | `/api/recordings/{id}/process` | Поставить обработку в очередь; использовать сохранённую расшифровку, если она есть |
| POST | `/api/recordings/{id}/process?mode=full` | Повторить распознавание и анализ |
| POST | `/api/recordings/{id}/process?mode=summary` | Создать только резюме по сохранённой расшифровке |
| GET | `/api/recordings/{id}/result` | Расшифровка, резюме, тезисы |
| DELETE | `/api/recordings/{id}` | Удаление записи и результатов |

Для API-клиента: сохраните cookie из успешного входа и отправляйте её с запросами к записям. Для всех изменяющих запросов, включая вход/выход, нужен заголовок `X-Echo-Request: 1`. Если отправлен `Origin`, он должен совпадать с адресом приложения; внешние браузерные источники запрещены. Без cookie API возвращает 401, при нарушении проверки источника — 403. Чужие записи возвращают 404. Заголовок `X-Echo-Account` необязателен для API-клиента; интерфейс использует его для защиты от смены аккаунта в другой вкладке. Несовпадение с текущей сессией возвращает 409. Сам заголовок не даёт прав доступа.

## Замечания

- Для корректного воспроизведения поддержка аудиокодека должна быть в браузере. Оригинал всегда можно скачать.
- Временные файлы обработки Whisper/FFmpeg создаются только на время вычислений и удаляются после задачи; **постоянное хранение** аудио — в PostgreSQL.
- Расшифровка содержит реплики с временными метками. При включённом разделении голосов они помечаются «Собеседник 1», «Собеседник 2» и т. д.; имена и профессии автоматически не угадываются.
- При аварийном завершении задача возвращается в работу после истечения блокировки (до 90 секунд после последнего продления, плюс ожидание свободного обработчика). При штатном завершении незаконченные задачи возвращаются в очередь сразу.
- В интерфейсе поиск сейчас работает только среди **последних 100 записей**, а статистика считает все записи в БД.

## Очередь и восстановление

При первом запуске обновлённого сервера автоматически добавляются поле `processing_stage` и таблица `processing_jobs`. Существующие записи и результаты сохраняются. Зависшие задачи старой версии переводятся в новую очередь. Перед обновлением рабочей базы рекомендуется иметь резервную копию.

По умолчанию выполняется одна задача; `PROCESSING_WORKERS` позволяет задать от 1 до 8. Каждый сервер запускает указанное число обработчиков; очередь общая, одна запись имеет одного действующего владельца. Повторный запрос для уже активной задачи возвращает HTTP 202 без создания дубликата. Ответ содержит `queued: true`, если создано новое задание, иначе `false`.

Статус `processing` сопровождается этапом `queued`, `transcribing` или `summarizing`. При сбое распознавания либо Ollama задача получает `failed` с причиной. Ошибки моделей не повторяются бесконечно: после исправления причины нажмите повторную обработку или «Создать резюме». Прерванные перезапуском задачи подбираются автоматически. Уже сохранённый текст при этом повторно не распознаётся.

## Если долго создаётся резюме

Для обычного пересказа рассуждения Qwen3 по умолчанию отключены (`think: false`). Короткие заметки (до 600 символов расшифровки) получают одно предложение резюме и до двух дополнительных тезисов; лимит ответа — не более 256 токенов. Для более длинных записей используется до трёх предложений и пяти тезисов, с общим лимитом `OLLAMA_MAX_TOKENS` (по умолчанию 768).

Дополнительные параметры необязательны; без изменений рабочего `.env` применяются такие значения:

```dotenv
OLLAMA_THINK=false
OLLAMA_MAX_TOKENS=768
OLLAMA_KEEP_ALIVE=5m
```

`OLLAMA_MAX_TOKENS` принимает значения от 128 до 8192. Для коротких заметок без рассуждений применяется меньший из этого лимита и 256. Если другая модель требует рассуждений, можно задать `OLLAMA_THINK=true`; тогда действует полный заданный лимит, а обработка может заметно замедлиться. Незавершённый JSON при исчерпании лимита считается ошибкой; сохранённая расшифровка остаётся доступной. `OLLAMA_KEEP_ALIVE` определяет время удержания модели в памяти между запросами; `0` выгружает её после ответа. По умолчанию Ollama также использует 5 минут — этот параметр добавлен для настройки, а не как самостоятельное ускорение.

В журнале сервера отдельно выводится время распознавания и резюме. Строка `ollama model=... load=... prompt=... generate=... tokens=... thinking=...` помогает отличить загрузку модели от обработки текста и генерации ответа. Расшифровка и рассуждения модели в эти журналы не записываются.

После обновления перезапустите сервер и нажмите «Создать резюме» или «Обновить резюме» у записи. Повторное распознавание аудио для этого не нужно. Увеличение `PROCESSING_WORKERS` ускоряет очередь только при наличии свободных ресурсов и не ускоряет резюме одной записи на загруженном CPU.

Воспроизводимый замер с синтетической короткой расшифровкой: `./scripts/benchmark-summary.ps1`. Только новый режим: `./scripts/benchmark-summary.ps1 -Mode after`. На тестовом Ryzen 7 5700U с Qwen3 4B на CPU старый запрос за 117,51 с исчерпал тестовый лимит 1024 токена на рассуждения и не выдал ответа; новый выдал корректное резюме за 15,74 с. Это один замер с моделью, уже загруженной в память; время для ваших записей зависит от длины текста и нагрузки. Подробности: `validation/performance.md`.

## Черновики на устройстве

Черновики привязаны к браузеру и адресу приложения (включая порт). Они не синхронизируются между устройствами. Сохраняются только фрагменты, которые браузер успел выдать и записать в IndexedDB; последние мгновения перед аварией могут отсутствовать. Блокировка экрана и работа микрофона в фоне зависят от браузера и ОС.

На странице появляется блок «Несохранённые записи». Откройте черновик, прослушайте его и сохраните в базу либо скачайте аудио. После успешной отправки локальный черновик очищается. «Записать заново» удаляет текущий черновик после подтверждения. В браузерах с Web Locks один черновик нельзя одновременно открыть в двух вкладках.

При нехватке места или недоступности IndexedDB приложение сообщает об ошибке и сохраняет аудио в памяти до закрытия страницы: в таком случае сразу скачайте запись. Очистка данных сайта, приватный режим или удаление браузерного хранилища могут удалить черновики; они не заменяют резервную копию.

## Проверки для разработки

```powershell
go test ./...
go vet ./...
node --check web/app.js
node --check web/auth.js
node --check web/drafts.js
```

Для интеграционных тестов задайте `TEST_DATABASE_URL` с доступом к тестовой PostgreSQL и запустите `go test ./... -count=1`. Каждый тест создаёт уникальную схему `echo_test_*` и удаляет только её при завершении; таблицы приложения не используются. Без этой переменной проверки PostgreSQL пропускаются. Проверяются одновременные запросы, восстановление блокировки, запрет записи устаревшим обработчиком, сохранение текста при сбое Ollama и штатное завершение сервера.

Для изолированной проверки интерфейса: `node tests/web-server.cjs`, затем откройте `http://localhost:18080/` и `http://localhost:18080/storage-tests`. Сервер использует тестовые API-ответы и синтетический звук вместо микрофона; рабочая база и реальные модели не задействованы. На втором адресе кнопка запускает десять проверок IndexedDB, включая изоляцию пользователей.


Для браузерной проверки **настоящей авторизации** на временной схеме PostgreSQL:

```powershell
$env:ECHO_AUTH_PREVIEW = '1'
# TEST_DATABASE_URL должен указывать на доступную тестовую БД.
go test ./internal/handler -run TestBrowserPreview -v -count=1 -timeout 15m
```

Откройте `http://localhost:18080/`. Создавайте только тестовый аккаунт: схема стенда удаляется при завершении. В этом стенде используется настоящий API записей с отдельной тестовой схемой, модели ИИ не запускаются. Загружайте только синтетическое аудио. Он завершается автоматически через 12 минут или при корректной остановке. Обычный Node-стенд подменяет статус входа и предназначен для проверки интерфейса/микрофона, а не безопасности авторизации.


## Названия по содержанию и разные голоса

После обработки Ollama создаёт короткое название в том же запросе, что резюме. Оно хранится в `recordings.title`, показывается в библиотеке и карточке, участвует в поиске и используется при скачивании аудио. Оригинальное имя файла остаётся в `filename`. Чтобы дать название старой расшифровке, нажмите «Обновить резюме».

Для разделения людей используется локальный sherpa-onnx: модель сегментации pyannote 3.0 и голосовые признаки NeMo TitaNet Small. Учётная запись, токен и платный API не нужны. Официальная документация: https://k2-fsa.github.io/sherpa/onnx/speaker-diarization/models.html

Установка на Windows (Python 3.12 или 3.13):

```powershell
.\scripts\setup-diarization.ps1
```

После установки добавьте в `.env`:

```dotenv
DIARIZATION_ENABLED=true
DIARIZATION_PYTHON=.venv-diarization\Scripts\python.exe
DIARIZATION_THRESHOLD=0.9
```

Перезапустите `go run .`. На этом компьютере зависимости и модели уже установлены, а разделение включено в локальной `.env`.

На Linux создайте окружение `python3 -m venv .venv-diarization`, установите `pip install -r scripts/diarization-requirements.txt` через его Python и запустите `scripts/download-speaker-models.py`. В `DIARIZATION_PYTHON` укажите `.venv-diarization/bin/python`.

Whisper формирует текст с метками времени, затем модель голосов определяет интервалы собеседников; слова сопоставляются по пересечению интервалов. Неоднозначная одновременная речь остаётся без определённого голоса. Точность зависит от шума, длины реплик и сходства голосов. Порог `DIARIZATION_THRESHOLD` можно настроить: больше — меньше разных голосов. Разделение добавляет время к распознаванию.

При сбое модели голосов текст и резюме всё равно сохраняются, а интерфейс предлагает повторное распознавание. Реплики и состояние разделения сохраняются до запроса к Ollama, поэтому повтор создания резюме их не теряет. Для старых записей разделение появится после «Распознать заново».

Проверки моделей (не запускаются обычным `go test`): `TestLocalSpeakerModels` с `ECHO_SPEAKER_SMOKE=1` и открытым примером `models/diarization/test-four-speakers.wav`; `TestLocalContextTitle` с `ECHO_TITLE_SMOKE=1` проверяет Ollama на искусственной заметке. Для проверки Whisper нужно передать `WHISPER_CLI` и `WHISPER_MODEL` в окружении процесса теста.
